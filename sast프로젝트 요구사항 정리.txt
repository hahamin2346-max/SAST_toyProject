[SAST 검사의 4단계 기본 파이프라인]
[1. 소스 수집 & 격리] ➔ [2. 파싱 (AST / CPG 생성)] ➔ [3. 탐지 로직 (Engine)] ➔ [4. 결과 정규화]


시스템 기능 (SFR) :
	로그인 / 로그인 식별자 형식은 발주기관 별도 --> uuid 사용해서 할당하자
	로그인 인증 수단 / 유효기간, 검증절차 관리 
	일반 계정, 관리자 계정 구분, 권한 관리 
		- 관리자는 대상 프로젝트 정보 등록, 조회, 수정 가능 
		- 관리자는 프로젝트 별 사용자 할당 및 해제 가능
		- 일반은 권한을 받아야 조회가능
		- 관리자는 프로젝트 단위 정적 분석 가능
		- 일반 사용자는 프로젝트별 분석 이력, 분석 건별 진단 결과 목록 및 진단 결과 상세 정보 조회 가능
		
	분석할 코드 등록은 제안 방식에 따라 등록 및 관리 / 업로드, 저장소, 경로
	과정은 소스 수집, 코드 구조 분석, 진단 실행, 결과 정규화 의 분석 처리
	나온 결과에 대해 추적성과 재현성 보장 (잘못된 코드 위치 보기 뭐 그런거인듯?)
	언어를 추가했을때 추가 된 언어도 대응이 가능해야함
	초기 대상 언어는 Java, Javascript, Python / 동등하게 진단
	신규 진단 항목을 추가 할 수 있어야 한다.(공통된 등록 절차). 단, 기존 분석에 피해가 없도록
	 KISA의 보안 가이드 49개의 약점 항목을 정리해서 관리할 수 있는 칸을 만들자 (식별자, 항목 번호, 명칭, 설명, 구현 여부)
	진단 결과 관리 ->뭐가 잘못됐는지, 어떤 취약 코드인지 식별자까지, 심각도, 신뢰도, 위치, 경로, 메세지, 근거 등
	분석 상태 관리 - 대기, 진행, 완료, 실패 / 실패시 실패 원인 표시
	사용자 개인의 분석 이력과 해당 분석 조회
	진단 결과들을 속성별 필터링 기능 (심각도, 유형별 등등)

데이터 요구사항 (DAR) :
	영속 데이터는 믿을만한 데베에 잘 저장, 보관하고 스키마 변경 이력을 관리
	각 계정의 고유 식별자를 두고 비번 검증, 역할, 활성 상태, 생성 및 수정 시각 잘 저장
	프로젝트는 이름, 설명, 소스유형, 언어, 저장 위치, 생성 수정 시간 저장
	프로젝트별로 해당 프로젝트의 접근 가능 여부는 따로 저장 및 판별
	분석 실행 데이터는 어떤 프로젝트 분석했을때 그 프로젝트, 방식, 언어, 실행 상태, 실행한 사람, 시작 종료 시간, 오류 정보 등 저장
	진단 결과 데이터는 '진단한 결과에 대해' 항목 식별자, 명칭, 기준, 언어, 심각도, 신뢰도, 파일 위치, 메시지, 근거, 조치 권고, 원본 결과를 저장
	진단 기준 데이터는 진단 항목 식별자, 명칭, 설명, 기준 식별자, 분류, 항목 번호, 참조 정보, 활성 여부 및 기본 심각도를 관리
	과거의 분석 결과를 보존할 것(과거의 약점 식별자, 명칭, 기준, 언어, 심각도, 신뢰도 등) -> 진단 히스토리를 만드는걸로 생각하자
	분석 실행의 요약과 진단 결과처럼 구조화된 정보들을 조회와 보존 가능하도록
	사용자-프로젝트, 프로젝트-분석 실행, 분석 실행-진단 결과의 관계 무결성을 보장
	
보안 (SEC) :
	비밀번호는 단방향 암호화 해서 보호할 것, 평문 저장 및 출력 금지
	인증이 필요한 작업들은 인증 없으면 차단
	인증은 인증 정보의 발급ㆍ검증ㆍ만료 정책
	프로잭트 생성, 수정, 권한관리, 분석 실행, 분석 오류 정보 조회는 관리자 권한으로 제한
	즉, 관리자만 생성 수정 권한 변경, 분석 실행이 가능하고 일반 사용자는 분석 결과를 읽기 전용으로만
	일반 사용자 개인 식별자로만 권한 확인하지 말고 프로젝트 관계나 다른 조건도 보고 접근을 검증하라
	비인가 정보 노출 방지. 권한 없는 프로젝트에 대해 열람 및 요청 제한
	분석 대상 소스를 작업 영역 밖에서 접근할 수 없도록. 또한 대상 소스는 항상 격리해두기
	분석 대상 소스나 분석 프로젝트를 올리는 과정에서 경로 조작, 심볼릭 링크 악용, 비정상 경로의 접근은 방지
	자원 고갈을 이르키는 분석 실행 시도와 비정상 장기 실행을 통제하고 오류 정보와 로그는 권한 있는 사용자만 열람
	외부 솔루션이나 오픈소스를 이용하면 해당 소스 취약점, 라이선스, 버전 관리 방안이 필요

테스트 (TST) :
	시스템 관리자와 일반 관리자의 접근 관리 / 인증 수단 테스트, 인증 안된 접근 차단
	관리자의 일반 사용자 권한 허용과 제한에 대한 테스트
	일반 사용자의 프로젝트 할당 관리 테스트
	소스 수집, 분석 대상의 언어 식별, 코드 구조 분석, 진단 항목별 실행, 결과 도출이 잘 되는지 검증
	취약소스 정상소스 예제로 기대 결과 보고 항목별 탐지 결과 정확성 테스트
	kisa의 보안진단 49항목이 잘 관리되고 있는지
	분석 실행 후 상태, 진단 결과 저장, 조건별 필터링, 상세 조회 및 진단 기준 정보 연결이 정상 동작하는지 검증
	유효하지 않은 분석시 오류 정보와 재확인 절차가 관리 되는지 검증
	인증ㆍ권한, 프로젝트 관리, 데이터 관리, 분석 처리, 진단 항목 및 결과 관리 기능은 책임에 따라 분리. 모듈화
