# SAST 기능 추가 로드맵

## 목표와 제약

- 현재 확정된 UI를 기준선으로 유지한다.
- 기능 추가는 기존 화면 구조와 컴포넌트를 재사용하고, 레이아웃 변경은 기능에 필요한 최소 범위로 제한한다.
- 현재 프론트엔드 목업 데이터(`web/app.js`)를 백엔드 API(`sast_platform/api.py`)와 단계적으로 교체한다.
- 각 단계는 독립적으로 테스트 가능하고, 완료 후 다음 단계로 진행한다.

## 권장 구현 순서

### 1. 인증 및 세션 연결

- `web/app.js` 로그인 폼을 `/api/auth/login`과 연결한다.
- Bearer 토큰을 세션 저장소에 보관하고 로그아웃 시 제거한다.
- 인증 실패, 만료, 서버 오류 상태를 현재 로그인 UI에 연결한다.
- 완료 기준: 잘못된 계정은 오류를 표시하고, 올바른 계정은 대시보드로 이동하며 보호 API에는 토큰이 전송된다.

### 2. 프로젝트 실제 데이터 연결

- 대시보드 프로젝트 목록을 `/api/projects` 결과로 렌더링한다.
- 프로젝트 등록 모달을 실제 입력 폼으로 전환하고 `/api/projects`에 등록한다.
- 관리자/일반 사용자별 프로젝트 노출 및 접근 불가 상태를 API 결과로 표시한다.
- 필요 API: 프로젝트 수정/삭제, 사용자별 프로젝트 권한 조회.
- 완료 기준: 등록한 프로젝트가 새로고침 후 API 기준으로 표시되고, 권한 없는 프로젝트는 접근할 수 없다.

### 3. 진단 실행·이력·결과 연결

- 대시보드의 프로젝트 선택과 `진단하기` 버튼을 분석 API에 연결한다.
- 실행 중/완료/실패 상태를 현재 상태 배지로 표시한다.
- 진단 히스토리를 프로젝트별 실행 목록으로 교체하고, 실행 결과에서 심각도·신뢰도·메시지를 표시한다.
- Finding 상세 모달을 실제 파일 위치, 근거, 권고사항으로 채운다.
- 완료 기준: 분석 실행 1건이 히스토리에 나타나고 결과 상세까지 추적된다.

### 4. 탐지 규칙 관리 실제화

- `/api/rules`를 규칙 관리 화면과 KISA 가이드에 연결한다.
- 활성/비활성 변경과 추가/해제를 서버 상태로 저장한다.
- 규칙 변경이 다음 분석 실행에 반영되도록 분석 서비스와 연결한다.
- 완료 기준: 규칙을 추가·해제한 뒤 새로고침해도 상태가 유지되고, 분석 결과에 적용 규칙이 반영된다.

### 5. 진단 언어 관리

- 지원 언어 목록을 서버가 관리하도록 확장한다.
- `관리 언어 추가` 버튼에 추가 폼과 중복/미지원 언어 검증을 연결한다.
- analyzer registry(`sast_platform/analyzers.py`)의 지원 상태와 UI 상태를 일치시킨다.
- 완료 기준: 지원 언어를 추가·비활성화할 수 있고 프로젝트 등록 시 해당 언어만 선택된다.

### 6. 사용자·프로젝트 권한 관리

- 사용자 목록, 프로젝트별 멤버십 조회/부여/해제 API를 추가한다.
- 사용자 권한 화면의 목업 행을 실제 데이터로 교체한다.
- 관리자 전용 기능과 일반 사용자 읽기 전용 흐름을 API와 UI 모두에서 검증한다.
- 완료 기준: 권한 부여 전후로 프로젝트·진단 결과 조회 가능 범위가 바뀐다.

### 7. 영속 저장소 및 운영 보강

- 메모리 저장소를 SQLite 또는 확정된 관계형 DB 어댑터로 교체한다.
- 마이그레이션, 실행 이력 보존, 오류 로깅, 분석 작업 격리를 추가한다.
- 완료 기준: 서버 재시작 후 사용자·프로젝트·규칙·분석 이력이 보존된다.

## 공통 검증 규칙

- 기능 단계마다 기존 `python -m unittest discover -s tests -v`를 통과한다.
- 백엔드 API는 인증/권한/정상/오류 케이스를 단위 테스트로 추가한다.
- 프론트엔드는 `node --check web/app.js`와 주요 화면 수동 smoke test를 실행한다.
- UI 고정 원칙에 따라 화면 캡처 비교 또는 DOM 셀렉터 검증으로 제목, 상태, 버튼 위치가 유지되는지 확인한다.

## 첫 구현 권장 범위

다음 작업은 1단계 인증 연결부터 시작하는 것이 좋다. 이후 모든 화면이 동일한 사용자·토큰·권한 컨텍스트를 공유할 수 있어 프로젝트와 진단 기능의 재작업을 줄일 수 있다.
